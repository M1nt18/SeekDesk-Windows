## 客户端慢加载的原因与修复

1. 隐藏读取页等待完整 `load`，正文已经就绪仍在等待图片、字体、媒体或 iframe；静态资源缓存又被整体禁用。
2. 正文与账号、通知、个人空间共用串行队列；后台接口慢时，点击帖子必须排队。
3. 可选作者资料初始化还会再加载一次当前长帖。
4. 普通连接失败、超时也会设置全局 60 秒验证冷却，让后续刷新直接失败。

本版让隐藏读取页在 DOM 与实际样式就绪后提取，使用同一受限 renderer 的 CDP 执行，避免 `executeJavaScript` 隐式等待完整 load。只在隐藏目标跳过 Image/Font/Media，官方登录窗口不受影响；样式明确等待完成或失败，以维持官网隐藏规则。恢复脚本/样式缓存，每次正文导航仍发送重新验证请求，并去除楼层 hash 以保证同页重新读取。

只读接口与作者资料复用原有资料窗口和独立串行队列，不新增第三个隐藏窗口。账号接口先加载新官网文档核对身份；真正的发帖、编辑和互动继续在原文档队列执行，保留权限、账号代次与提交保护。作者资料仍按 Pro 的 300 ms 间隔渐进读取全部作者。只有实际验证或异常跳转进入验证冷却。

| 场景 | 修改前 | 修改后样本 |
| --- | ---: | ---: |
| 帖子有 2200 ms 慢图，首次正文返回 | 2296 ms | 209 ms |
| 第二篇慢图正文返回 | 2216 ms | 39 ms |
| 后台账号 API 延迟 1800 ms 时读帖 | 1817 ms | 43 ms |
| 同 URL 刷新且旧图片尚未结束 | 原来须等待完整加载 | 34 ms，返回新 revision |
| CSS 延迟 350 ms | — | 374 ms，隐藏内容仍隐藏 |

合成延迟用于隔离瓶颈，不代表真实网站毫秒级 SLA。真实匿名公网低频读取：修改前首页完整提取 6195 ms，修改后最终样本 2341 ms；相同会话中普通 Chromium 完整 load 分别为 2908/3083 ms。修改后公开帖子 1117 ms，`source:web`，读取到官网正文而非 RSS 摘要。公网样本数量少，受网络及验证状态影响；最后一次额外匿名身份页触发了站点验证，不代表已登录场景已全部验收。未读取用户已有浏览器配置、Cookie、账号或密钥。

原始本地计时在 `verification/reading-*-timing*.json` 与 `verification/reading-performance*.json`，不随安装包发布；可提交的摘要在 `.ecc/benchmarks/`。`npm run test:reading-performance` 对无关慢图/后台任务设置 1200 ms 回归门槛，同时验证新内容、样式隐藏、换号、资料队列和失败恢复。

## Pro 增量能力与条件性加固的评估

外部报告第 5 节明确将这些列为“值得评估”的增量，而非全部确认缺陷。本版不把原生尚未实现的功能写成已支持：关键词提醒已有，阅读内关键词高亮/隐藏规则、Callout、普通代码语言高亮、分组回复、UID 备注仍属后续增量；历史已有 200 条边界，按天数/自定义数量保留尚未提供。这些需要独立产品选项、净化和滚动定位验证。

原插件继续只增强官方页面；隔离世界的 DOM/菜单运行和密钥持久化已实测，依赖官网 `__vue__` 的每种分组回复分支不在本轮真实账号写入验收范围。DNS 重绑定和独立更新签名属于外部报告的条件性加固，本轮未证明可利用问题，也未宣称完成独立签名。现有 HTTPS 来源、重定向限制与哈希校验保留。
