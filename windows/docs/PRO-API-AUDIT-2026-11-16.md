# Nodeseek Pro 1.0.8 接口核对

本次针对仓库内固定的 [Nodeseek Pro 源码](../vendor/nodeseek-pro/nodeseek-pro.user.js) 检查网络包装器、全部 `net.get/post`、原生 `fetch` 和 `GM_xmlhttpRequest` 调用。版本仍为 0.1.2，本记录随接口修复包发布；第三方原脚本未修改。

| Pro 实际使用的请求 | React / Electron 对应处理 | 本次结果 |
| --- | --- | --- |
| `GET /api/account/getInfo/{uid}` | 用户资料卡、作者等级、角色、关注状态和加入时间 | 卡片改用相同的基础地址，不再依赖额外 README/签名权限；他人主页仅追加原版支持的 `readme=1`，本人编辑保留完整签名读取和冲突检查。 |
| 资料请求串行队列，每位作者读取前等待 300 ms | `MemberProfilesService` | 生产配置改为串行、间隔 300 ms；保留每页全部作者、3 分钟缓存、相同 UID 去重、超时、明确重试及账号切换取消。没有重新加入作者数量上限。 |
| `POST /api/block-list/add`，JSON 为 `block_member_name` | 用户资料卡 → 官网黑名单 → 加入 | 新增。用户确认后，根据选中 UID 先读取官网当前名称，再提交，避免旧名字或界面伪造名字指向另一账号。 |
| `POST /api/block-list/del`，JSON 为 `block_member_id` | 用户资料卡 → 官网黑名单 → 移出 | 新增。按 UID 移除；读取操作页使用官网首页，不要求被移除对象的个人主页仍存在。 |
| `POST /api/attendance?random=true/false` | 签到扩展 | 路径和随机模式语义已一致；保留按账号和日期去重、签到前状态核对、用户开关与北京时间调度。未照搬重复写入。 |
| `GET /api/notification/unread-count` | 顶栏未读数和三类通知 | 已使用同一接口；保留分类计数、账号检查和选择预览与标已读分离。 |
| 下一页链接的同源 HTML `GET` | 评论自动续读 | 已有对应读取；下一页来自真实分页，保留楼主/HOT 去重、实际操作页、阅读锚点、错误重试与停止条件。Pro 没有提供另一个免登录评论接口。 |
| `POST https://api.nodeimage.com/api/upload`，表单字段 `image`、请求头 `X-API-Key` | 原生图片上传和统一 Markdown 编辑器 | 已使用同一接口；密钥仍由用户配置并以 Windows DPAPI 保存，保留图片尺寸处理、发送前上传保护及草稿。 |
| `GET https://api.nodeimage.com/api/user/api-key` | 图床账户取密钥 | 依赖单独的 NodeImage 登录 Cookie。未把论坛 Cookie 当作图床会话，也未将浏览器 Cookie 转发给脚本网络桥；原生端继续使用用户明确配置的密钥。不能把这个接口称为免登录自动取密钥。 |
| 可配置 AI 地址的 `POST`（默认 OpenAI Chat Completions），以及同地址连接测试 | Pro 中的可选 AI 模块源码 | 此固定脚本在加载前设置 `AI=false`，实际不启用该模块。本次不改变开关、读取密钥或发出模型请求，也不放宽网络桥的域名限制。 |
| Layui、highlight.js 和样式 CDN | 固定脚本依赖/本地适配资源 | 属于前端资源，不是论坛资料接口。继续校验固定文件、保留第三方许可证。 |
| `seek.li`、GreasyFork 反馈及更新页面 | 外部页面链接 | 不是可替换资料/评论读取的接口。 |

Pro 的“好友备注”保存在脚本本地，不能当成论坛关注接口；Windows 原生关注仍使用原版的 `/api/fans/add`、`/api/fans/del`。Pro 的本地折叠和官方黑名单也是不同操作，本次保留原生“屏蔽用户”作为本机过滤，官网加入/移除则在资料卡中独立确认，成功仅以服务端明确回应为准。

## 验证与边界

- 263 项单元/契约测试，以及资料卡、真实主进程/预加载、黑名单确认/取消/重复点击/拒绝重试、资料队列节奏与换号取消回归。
- 写入、上传和安装调用全部使用合成响应或可注入适配器，没有对真实论坛执行黑名单、签到、回复、私信或上传测试。
- 匿名实际请求资料接口返回 403 站点验证页，不能据此宣称已在用户真实登录权限下读取成功。此包修复已确认的请求差异，保留官方窗口用于用户登录和验证。
- Pro 也支持 DeepFlood；Windows 客户端仍按既有范围只承载 NodeSeek，不把另一个站点的会话混入本论坛。

同号重新打包不触发已安装 0.1.2 的版本比较更新；已经安装或缓存旧 0.1.2 的用户需下载此次文件，手动覆盖安装或替换便携文件一次。未来更高版本的常规安装版更新改为后台静默替换并自动打开新版。
