# 原版功能核对与本轮修复

核对日期：2026-11-12。原版仓库 `cshaizhihao/SeekDesk` 的远程 HEAD 与本机 `upstream/main` 均为 `84e99c6cb24e66c5bbccb6382380ae72b9924d4b`，已核实没有拿旧版功能表代替当前原版。

核对材料：`README.macOS.md`、`Sources/SeekDesk` 的实际 Swift 界面与请求实现，以及 Windows 的 React → preload → IPC → 主进程 → 官方请求 → 界面状态链路。用户指定的计算器、友情链接、GitHub 源等改动继续按用户要求保留。macOS 原生材质等平台实现不当成 Windows 缺失的按钮。

本轮共确认并处理 **32 项问题**，按下表的功能问题计数；同一功能中的字段、样式或竞态修复不重复累计。并非只改说明文案，个人时间、通知预览、私信模式等均补了数据链和行为测试。

## 验证记录

- `npm run build`：前端和 Electron TypeScript 检查及构建通过。没有执行安装包构建。
- `npm test`：177 项单元、解析器、权限、缓存与存储测试全部通过。
- `profile-space-smoke.cjs`：7 组隔离 Electron 检查，验证先列表后时间、真实日期补读、重试、概况、账号设置、轻资料卡、暗亮与窄屏、离开后迟到响应。
- `inbox-ui-smoke.cjs`：通知精确楼层预览、分类计数、旧联系人、纯文本读写、最新定位、设置草稿保护及无渲染异常。
- `profile-pagination-smoke.cjs`：7 组隔离 Electron 检查。14 位作者全部调度，最大并发 3；超过旧上限的作者、等级 0、1.8 秒响应、失败重试均覆盖；补资料时滚动位置为 420 → 420；顶部和底部从第 3 页直回第 1 页；旧页与旧账号结果不回填。
- `npm run test:app`：后端、完整界面、阅读器、内嵌官方登录的模拟流程通过。
- `npm run test:reply-refresh`、`npm run test:desktop`：回复只提交一次、后续只读重试、窗口与更新、HOT 和折叠回复流程通过。

测试使用隔离的应用数据目录与合成账号。通知已读、私信、发帖、关注、鸡腿等写请求均为模拟，没有向真实论坛发送。

## 公开实测与仍需用户会话验收的部分

匿名公开 GET 实测读到了帖子 `893437` 的 14 个楼层、13 位作者，以及真实的 `1、2、3、4、5、51` 页链接，正文读取和分页提取成功。

同一隔离匿名会话中的 `/api/account/getInfo/{UID}` 返回 **403、text/html 站点验证页**，所以这次没有把真实线上等级读取记作成功。程序会保留正文，显示资料读取失败/验证提示，提供官方页面验证和重试入口。所有作者完整加载与账号隔离已由合成 Electron 测试验证，真实权限仍需用户在官方窗口登录或验证后验收。

真实账号的受限帖子、通知/私信、资料保存、发帖/编辑、关注、签到以及付费互动没有代用户线上操作。它们已有实际处理链与模拟测试，但不能用模拟成功代替线上授权和站点响应。原版与 Windows 的每页短期内存缓存策略不同；Windows 记忆当前标签的页与滚动位置，主动翻页按本次要求回到页首。
