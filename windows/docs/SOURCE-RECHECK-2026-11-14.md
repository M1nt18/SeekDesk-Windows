# 2026-11-14 原版源码复核

本文件记录发布前的实现与验收，现纳入 Windows 0.1.2；原文件名和历史阶段说明保留。正式内容见 [0.1.2 发布说明](releases/v0.1.2.md)。

本轮对照的是 `cshaizhihao/SeekDesk` 当前 HEAD `84e99c6cb24e66c5bbccb6382380ae72b9924d4b`。原版 Swift 文件未改动；Windows 上一轮尚未发布的一键更新、等宽标签和连续阅读继续保留。

此前核对把部分“已有入口、能够请求到数据”记作完成，漏查了只读内容的实际排版、原版条件分支、未读操作、副作用以及离开页面后的写入结果。本轮按原版界面、字段、事件、请求、最终状态分别核对，以下为本轮修复的具体项目。此表不把截图中出现按钮或模拟请求成功等同于真实账号线上验收。

## 用户本次指出的问题

| 项目 | 对照与修正 |
| --- | --- |
| 单页显示两组分页 | `ThreadPagination` 和其底部容器仅在存在第二页的证据时显示；不以楼层数量判断。单层或多层但只有一页均隐藏。 |
| 写回复按钮靠左 | 收起状态的写回复移到右侧，草稿提示在左；展开后的关闭按钮仍在右侧，关闭不清草稿。 |
| 个人信息 Markdown 不完整 | README 已有语法解析但缺表格样式，简介和签名还在输出纯文本。现在共用安全 `ProfileMarkdown`，含表格边线、表头背景、内边距、横向滚动、列表、引用、代码及链接。 |
| 五项统计无背景 | 对照 `ForumSpacePane` 的统计卡恢复常态 surface 填充、圆角与 12px 内边距；保留零值、本人目录权限和统计跳转。 |

| `ForumUserCard.UserBadges`、本人签名优先级 | 多个角色挤成一枚徽章；本人签名保存后还显示旧缓存 | 独立角色色块；保存成功通过受账号版本约束的回调更新本人签名，不抢回导航。 |
| 直链打开 | 搜索中的指定页链接遇到已打开标签时未重新定位 | 直链按显式导航处理，包括目标分页和楼层。 |

## 写入、通知、扩展与设置

| 原版依据 | 原来遗漏 | 修正 |
| --- | --- | --- |
| `NewDiscussionView.canPublish`、`ThreadReader.canSendReply` | 图片上传未结束，父级按钮仍能发送旧正文 | 图片和本机表情共用同步上传状态，父级提交复核；卸载后的旧上传不插入新稿。 |
| `NewDiscussionView` 发送快照 | 发送中仍可改标题/权限或离开，旧结果可能清新稿、抢回导航 | 控件锁定，并按账号、草稿键、操作和快照协调，原地与全页编辑复用同一保护。 |
| 已接受写入的生命周期 | 服务端成功后离开或重开编辑器，旧快照可能仍保留为可发送草稿 | 主题与私信共享提交快照协调；不清除后来修改的新稿，区分服务端成功与本机清理失败。 |
| `ForumAccountSheet` 已读按钮 | 预览通知、打开私信会自动写已读 | 预览与独立红点/标已读操作分开，保留失败重试和成功反馈。 |
| `ForumAccountSheet` 主从布局 | 打开会话后整个列表消失 | 联系人与分类持续显示，右侧展示通知或会话；切换前保存本地草稿并隔离旧响应。 |
| `ProfileIntroductionEditor` | 无修改也可保存；刷新覆盖编辑；成功仍留在简介 | 无修改禁用保存，刷新不覆盖编辑，成功回概况；离开后的成功签名仍可安全回填。 |
| `PluginCenterView`、`DeskExtensions` | 统一网格/弹窗替代分组与整页详情；移除/停用部分设置关系不同 | 恢复已安装/未安装分组、单色图标、状态色块和整页详情；复原自动项与停用操作关系。 |
| 原版通用偏好 | 缺自动检查应用更新的开关 | 默认开启并持久化，关闭只停止自动检查，不影响手动更新及缓存清理。 |

## 验证与边界

验证使用隔离应用目录和合成账号；论坛写入、上传和原生安装器均由测试替身接收，没有代用户发布、编辑、发送私信或执行安装。个人 Markdown、阅读控制、通知分栏、上传/提交、扩展与更新偏好分别有独立 Electron 回归，既有完整应用回归继续保留。

发现的原始证据保留在 [阅读源码复核](reader-reaudit-2026-11-14.md)、[应用源码复核](application-reaudit-2026-11-14.md) 与 [设置/扩展复核](settings-extension-reaudit-2026-11-14.md)。其中 Windows 行号记录的是审计当时状态，不应当作修复后代码的当前行号。

这轮仍为本地未发布修改；没有用真实账号写入验证权限，也没有在用户的真实安装上验证 NSIS 跨版本安装。真实站点权限和验证状态需要在官方会话中验收，不能以合成测试替代。
